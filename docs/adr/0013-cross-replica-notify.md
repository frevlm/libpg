# 跨副本一致由数据库通知：语句级触发器加 NOTIFY，定期全量对齐兜底

使用方声明监视列后，迁移为它建立语句级 `AFTER INSERT OR UPDATE OF c OR DELETE` 触发器，把变化的主键用
`pg_notify` 发出（按 7000 字节切分）。每个写回缓存用一条专用连接 `LISTEN`，收到后对这些键做对齐；
自己写回线程发出的通知按 backend pid 忽略。监听连接重连后先全量对齐，另外每 60 秒全量对齐一次。

理由：revlm 有 2 到 6 个副本，各有一份内存余额。数据库知道哪些行变了，由它通知，任何写入方——别的副本、管理后台、
手工 SQL——都会被感知，透支上限从“5 秒的消费”缩小到“一个写回周期的消费”。

## Considered Options

- 应用每 5 秒调一次对齐：滞后大，并且管理员直写后要记得手动对齐。

## Consequences

- 带 NOTIFY 的事务提交时会争一把全库锁，提交被串行化；每副本每 200ms 一批，远低于上限。
- 对监视列的绝对值写入会覆盖别的副本还没写回的增量，使用方必须把这类列从普通 UPDATE 的 SET 里去掉。
