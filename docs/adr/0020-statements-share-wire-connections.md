# 事务外的语句共用线路连接，连接只在需要时独占

数据库在远端时（同区 RTT 0.5–1 ms），一条语句从发出到结果回来的整个往返里，服务端大部分时间是空闲的。
如果连接在往返期间被独占，max_conns 条连接最多只能跑 max_conns / RTT 条语句每秒；而使用方（HHHOJ）
的常态是线程数多于连接数（固定 8 条连接），多出来的线程只能排队借连接。

决定：

- 事务外立即执行的语句（`exec`、`query*`）在往返期间租用一条线路连接，同一条线路连接上可以同时有多个线程的语句：
  各自排一个 ticket、各自带一个 Sync，也就是跨线程的 pipeline。每条线路连接同一时刻只有一个线程在 poll，
  收到的结果按队列顺序分给各自的 ticket。
- 事务、`send`（未读完的语句）、`raw()` 和 `insert_all` 的 COPY 让 `conn` 独占一条线路连接，直到事务结束、
  语句读完或 `conn` 结束；独占的线路连接上没有别的线程的 ticket。
- 选择线路连接时：先取没人用的，其次在 `max_conns` 以内新开，最后取在途语句最少的、没被预留的线路连接；都没有就进入
  FIFO 等待队列。队头是共享的等待者时，拿到的线路连接可以同时给后面排着的共享等待者；队头要独占时，库预留一条
  共享的线路连接（新的共享借用跳过它），它的用户走完后交给队头，所以独占等待者不会被源源不断的共享借用饿死。
  等待超过 `acquire_timeout` 抛错。
- 线路连接断开时，上面排队的所有语句一起以 `broken` 失败，每个线程的下一条语句换新连接。

## Consequences

- 事务外的两条语句可能落在不同的服务端会话上，和事务池模式的池化器一样：`SET`、advisory lock、
  `currval` 这类会话状态要放进事务，或者用 `raw()`。需要它们的语句不会被库猜出来，使用方自己选。
- 线程数多于连接数时吞吐不再被 `max_conns / RTT` 限制，代价是同一条线路连接上先排的语句会让后面的多等它一次。
- 一条线路连接出错或断开时，只有它上面在途的语句受影响；语句级的服务端错误只影响发出它的那个 ticket。
