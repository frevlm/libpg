# 查询参数用 :name 占位符，两个以上输入生成一个结构体

查询文件原来在 `-- params:` 里给参数起名，正文写 `$1..$n`，C++ 调用按位置传。参数名、编号和实参顺序三处各对齐一次，全手工；同类型的两个参数写反了也能编译。

ADR 0008 当时不做词法扫描，理由是 `@name` 会撞上 JSONB 的 `@>`、`<@`、`?`。`:name` 不撞这些运算符，只和 `::`
类型转换、数组切片 `a[1:n]` 相邻；前者扫描时直接跳过，后者和 psql 的变量替换规则一样，要写成 `a[1 : n]`。扫描只在
生成器里做一次，运行时从不解析 SQL。代价是正文不再一个字节都不改：占位符在生成时改写成 `$n`。

## 决定

- 正文用 psql 的写法就地命名参数：`:name`，`:'name'` 等价。不同的名字按首次出现编号成 `$1..$n`，同一个名字复用编号。`::` 是类型转换，不是占位符。
- 扫描时跳过单引号字符串（含 `''`）、E 字符串、双引号标识符、美元引号（`$$…$$`、`$tag$…$tag$`）、`--` 行注释和 `/* */` 注释；洞 `/*@name*/` 仍按注释保留。
- 生成器在 PQprepare/Describe 和 format_body 之前把正文改写成 `$1..$n`，后面的参数类型、开头的参数注释、可空性推断都不变。
- 0 或 1 个输入（参数加洞）仍按位置传，没有可对错的地方。2 个以上输入生成 `<函数名>_params` 结构体，成员按首次出现顺序：参数用今天的 C++ 类型（文本是 `std::string_view`，标量和其他类型按值），洞是 `pg::sql`。调用方写 `f(c, {.id = 1, .name = s})`。C++ 没有具名实参，结构体加指定初始化器是唯一能按名字匹配两端的写法。
- 文件头出现 `-- params:` 时报错；正文里出现裸 `$1` 也报错；占位符名不是可用的 C++ 名字、或与洞同名时报错。

## Consequences

- 参数名写错或漏写由生成器报错，不再靠调用顺序碰巧正确。
- 多输入的函数多一个结构体，调用方要写字段名；0 和 1 个输入的签名不变。
- 文件仍是 psql 语法：`\set name value` 之后可以照原样执行。
