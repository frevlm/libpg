# 查询参数用 :name 占位符，两个以上输入生成一个结构体

如果参数写成 `$1..$n`、名字另放在文件头，名字、编号和实参顺序要三处手工对齐，同类型的两个参数写反了也能编译。
所以在正文里就地给参数命名。

`:name` 不撞 JSONB 的 `@>`、`<@`、`?` 运算符，只和 `::` 类型转换、数组切片 `a[1:n]` 相邻；前者扫描时直接跳过，
后者和 psql 的变量替换规则一样，要写成 `a[1 : n]`。扫描只在生成器里做一次，运行时从不解析 SQL。

## 决定

- 正文用 psql 的写法就地命名参数：`:name`，`:'name'` 等价。不同的名字按首次出现编号成 `$1..$n`，同一个名字复用编号。`::` 是类型转换，不是占位符。
- 扫描时跳过单引号字符串（含 `''`）、E 字符串、双引号标识符、美元引号（`$$…$$`、`$tag$…$tag$`）、`--` 行注释和 `/* */` 注释；洞 `/*@name*/` 仍按注释保留。
- 生成器把正文改写成 `$1..$n` 交给服务端 Prepare/Describe，参数和结果的类型由此得出；同时生成 `pg::sql` 格式串：每个占位符和洞的每次出现都是 `{}`，重复的名字把同一个实参再传一遍，字面量大括号写成双份。
- 0 或 1 个输入（参数加洞）仍按位置传，没有可对错的地方。2 个以上输入生成 `<函数名>_params` 结构体，成员按首次出现顺序：参数用 C++ 类型（文本是 `std::string_view`，标量和其他类型按值），洞是 `pg::sql`。调用方写 `f(c, {.id = 1, .name = s})`。C++ 没有具名实参，结构体加指定初始化器是唯一能按名字匹配两端的写法。
- 正文里出现裸 `$1` 报错；占位符名不是可用的 C++ 名字、或与洞同名时报错。

## Consequences

- 参数名写错或漏写由生成器报错，不再靠调用顺序碰巧正确。
- 多输入的函数多一个结构体，调用方要写字段名；0 和 1 个输入的签名不变。
- 文件仍是 psql 语法：`\set name value` 之后可以照原样执行。
