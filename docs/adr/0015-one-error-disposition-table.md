# 一张错误处置表同时决定池、闭包事务和写回缓存的行为

错误按情况分类（断连且在 COMMIT 前、COMMIT 期间断连、只读 25006、40001/40P01、55P03/57014、0A000/26000、
截止时间到、建连失败、22xxx/23xxx、其他），每类在一张表里同时规定：连接丢弃还是保留、闭包事务是否重试、
写回缓存重放还是逐笔隔离。没有第二套分类；v1 写回缓存里单独的“暂时性/永久性”分类随之取消。

理由：同一个 SQLSTATE 在不同地方被不同对待，正是生产事故的来源。错误的 `what()` 只含 SQLSTATE 和主消息，
SQL 文本单独存放，使用方把 `what()` 返回给客户端时不会泄漏 SQL。
