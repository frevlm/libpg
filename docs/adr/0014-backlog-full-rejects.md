# 积压超过上限时拒绝新的笔，而不是丢最旧的

写回缓存的积压（已记账、未结算的笔数）达到 `backlog_limit` 时，`submit` 直接抛 `backlog_full` 并且什么都不记录；
使用方在请求入口看 `stats().backlog` 做准入（例如返回 503），正常情况下这个异常不会触发。被永久放弃的笔
（关停超时、行已删除、约束错误）逐条交给使用方的 `on_lost` 回调，可以人工补账；没有回调时打印到 stderr。

理由：悄悄丢最旧的记录丢的是钱，库不替使用方决定丢什么。进程崩溃时尚未提交的笔会丢失（最多一个积压上限），
不做本地 WAL：revlm 是只读根文件系统，准入控制加丢失回调已经够用。
