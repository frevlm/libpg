# 迁移保持使用方的一事务语义，记账放进 libpg 自己的 schema

所有待执行迁移仍在一个事务里全部成功或全部回滚（两个使用方现在就是这样）。迁移记账、写回回执和监视触发器函数
放进 libpg 独占的 `libpg` schema，不借用使用方的表；第一次运行时从使用方的旧记账表导入已应用记录，旧表只读。
滚动发布过渡期同时拿 libpg 自己的 advisory lock 和使用方的旧锁（HHHOJ 是 20261018），新旧二进制仍然互斥。
拿锁用短 `lock_timeout`，遇到 55P03 回滚并退避重跑。

理由：`ALTER TABLE` 拿锁排队会让这张表的所有读写都排在它后面，几秒内就能把池打满，“短 lock_timeout 加重试”
是业界的标准解法。迁移内容做规范化（CRLF 转 LF、去行尾空白）后再求 SHA-256，Git 换行转换不会误报，
真正修改了已应用的迁移才会报错。

## Considered Options

- 沿用使用方现有的记账表：回执和触发器没有归属，而且要改使用方的表。
- 会话锁加 checksum、每个迁移一个事务：破坏现有的一事务语义。
