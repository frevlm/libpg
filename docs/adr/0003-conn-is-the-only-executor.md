# 连接是唯一的执行器；嵌套借用立即抛异常

用户面只有一种执行器：借出的连接（`pg::conn&`）。不做模板 concept，不做虚基类，池也不能直接执行语句；
在不在事务里是连接自己的状态，直写格子也绑定在连接上，因此天然参与事务。同一线程对同一个池嵌套借用时立即抛异常。

理由：使用方大量 `f(Db&, ...)` 非模板函数的签名可以原样保留。v1 里格子自己借连接、helper 随手传池，
导致同一线程嵌套借用，池满时死锁；禁止嵌套借用后，HikariCP 的死锁公式 `Tn × (Cm − 1) + 1` 里 Cm = 1，任何池大小都不会死锁。
tokio-postgres 为了统一 Client 和 Transaction 只好另加 GenericClient trait，sqlx 维护者建议直接收 `&mut PgConnection`，
sqlpp11 本身也把事务当作连接上的状态。
