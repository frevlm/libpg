# 写回缓存的原子单位是“一笔”，只支持计数器

写回缓存里的格子只有计数器（只读和累加）；写回的原子单位是一笔：若干插入行加若干增量，一起提交或一起放弃。
不提供按格子写回、写回赋值、`update(F)`、按唯一键定位的格子或 LRU 淘汰。

理由：revlm 的扣款是从流水推出来的，流水行和它引起的余额变化是同一个事实。按格子写回需要 set/delta 混合状态机，
还会引出锁序死锁、“结果未知时只重放 set”这类丢账规则，都是因为原子单位选错了。以后真需要“最后写入者为准”的寄存器，
再作为一笔里的第三种部件加入。

## Consequences

- 槽的不变式是“内存值 = 数据库值（最近一次读到的）+ 已记账未结算的增量”。写者只做原子加法，热路径不做 IO；
  槽按键分到 64 个带各自互斥锁的分片里，没有全局锁。
- 内存里不检查溢出；数据库列真的溢出时这一笔被撤回，内存自动回到正确值。
- 计数器的值类型是整数或 `pg::decimal<S>`，内部都按 int64 单位累加；键是表的主键。
