# 写回缓存的原子单位是“一笔”，只支持计数器

写回缓存里的格子只有计数器（只读和累加）；写回的原子单位是一笔：若干插入行加若干增量，一起提交或一起放弃。
v1 按格子写回、支持写回赋值、`update(F)`、按唯一键定位的缓存格子、LRU 淘汰，这些全部删掉。

理由：revlm 的扣款是从流水推出来的，流水行和它引起的余额变化是同一个事实。按格子写回时，set/delta 混合状态机、
`update(F)` 的锁序死锁、“结果未知时只重放 set”这类丢账规则都是因为原子单位选错了。删掉的能力都没有使用方；
按唯一键定位还要在热路径上多一次 SELECT。以后真需要“最后写入者为准”的寄存器，再作为一笔里的第三种部件加入。

## Consequences

- 槽的不变式是“内存值 = 已入库的值 + 已记账未结算的增量”，写者只做原子加法，热路径不拿全局锁、不做 IO。
- 内存里不检查溢出；数据库列真的溢出时这一笔被撤回，内存自动回到正确值。
